# Packed equality count SIMD measurements

Development measurement on an Apple M4 Max, Darwin 25.3.0 ARM64, Go 1.27.0.
Both builds use `GOEXPERIMENT=simd`; existing JSON and checksum acceleration
therefore remains enabled in both. The baseline is commit
`ea8665045570df3b7d3a3f9aee4d8d9bc4dba0ae` with only the new storeio and
query benchmark files copied into it. The candidate is the implementation accompanying this note.
No dependency, storage-format, or durability setting changes are involved.

Each row has ten 250 ms repetitions with `-cpu=1`. Tests and builds did not
run concurrently with measurements. The baseline ran first, then the
candidate. These are local warmed measurements; power and thermal conditions
were not controlled, and no cold storage or concurrency claim follows.

The deterministic fixture contains 4,096 rows. Labels use 128 distinct
17-byte strings generated by a fixed multiplicative permutation; integers
cycle a scrambled range of -512 through 511. The production encoder must
select dictionary width 7 and FOR width 10, or fixture creation fails.
Every timed operation checks an exact expected count. Each stripe benchmark
uses a real encoded and opened stripe and includes path resolution.

Median nanoseconds per operation, from [all baseline samples](before.txt)
and [all candidate samples](after.txt):

| Operation, 4,096 rows | Baseline | SIMD candidate | Speedup |
| --- | ---: | ---: | ---: |
| Packed 7-bit equality | 1,033.5 | 320.45 | 3.23× |
| Dictionary spelling equality | 1,226.5 | 538.75 | 2.28× |
| Packed 10-bit equality | 1,077.5 | 655.50 | 1.64× |
| FOR integer equality | 1,093.0 | 661.05 | 1.65× |
| Stripe dictionary equality | 1,290.5 | 614.65 | 2.10× |
| Stripe integer equality | 1,166.5 | 777.90 | 1.50× |

Every sample reports zero bytes and zero allocations per operation. These
rows measure the counter, stream, and stripe layers.

The separate short-input sweep uses five 100 ms repetitions of all-zero
packed inputs at counts 0, 1, 8, 16, 31, 32, and 64. The extra dispatch costs
about 0.5–0.8 ns for the measured nonempty inputs below 32 rows. At 32 rows,
the vector path improves 7-bit counting from 8.16 to 7.05 ns and 10-bit
counting from 8.85 to 7.21 ns. At 64 rows the respective improvements are
14.28 to 8.59 ns and 16.72 to 9.55 ns. This supports the 32-row threshold;
it does not claim a speedup for tiny calls. All [baseline](threshold-before.txt)
and [candidate](threshold-after.txt) diagnostic samples are retained.

Reproduce in each checkout with the identical benchmark file:

```sh
GOEXPERIMENT=simd go test ./internal/storeio -run '^$' \
  -bench 'Benchmark(CompactStream(PackedEquality(7|10)$|SpellingEquality7$|IntegerEquality10$)|CompactPrimaryStripePackedEquality(7|10)$)' \
  -benchmem -benchtime=250ms -count=10 -cpu=1

GOEXPERIMENT=simd go test ./internal/storeio -run '^$' \
  -bench '^BenchmarkCompactStreamPackedEqualityThresholds$' \
  -benchmem -benchtime=100ms -count=5 -cpu=1
```

## Durable query measurement

The query fixture uses the same formulas over 16,384 rows, written through
`durable.CreateFromPrimary` and reopened with the default durable options.
There are no overlays or declared indexes. A single reused executor and
snapshot run `Select(Count()).Where(Cmp(field, Eq, value))`, with one worker
and setup/warmup outside timing. The exact count and scan statistics are
checked before and after each timed loop: all rows take the token scan, with
no index bound, data skipping, rendered fallback, or materialized batches.

Ten 500 ms repetitions, baseline then candidate, both with SIMD enabled:

| Durable query, 16,384 rows | Baseline ns/op | SIMD ns/op | Speedup | Latency reduction |
| --- | ---: | ---: | ---: | ---: |
| Dictionary equality COUNT, 128 matches | 7,216 | 4,585 | 1.57× | 36.5% |
| Integer equality COUNT, 16 matches | 6,712 | 5,279 | 1.27× | 21.3% |

All [baseline](query-before.txt) and [candidate](query-after.txt) samples are
retained and report zero bytes and zero allocations per operation. These
measure the warmed native query API over a durable snapshot, including graph
traversal and count aggregation. They do not include SQL parsing, client
protocols, cold disk I/O, concurrent writes, or other predicate widths.

Separate CPU profiles prove the actual query stack reaches the new kernels:
the [label profile](profile-label.txt) includes the dictionary stream and
7-bit NEON counter; the [integer profile](profile-number.txt) includes the
FOR integer stream and 10-bit NEON counter. Profile runs are separate from
the timing samples above.

```sh
GOEXPERIMENT=simd go test ./query -run '^TestFilePackedEqualityCount$' \
  -bench '^BenchmarkFilePackedEqualityCount$' \
  -benchmem -benchtime=500ms -count=10 -cpu=1

GOEXPERIMENT=simd go test ./query -run '^$' \
  -bench '^BenchmarkFilePackedEqualityCount$/^label$/^dictionary7$' \
  -benchtime=2s -count=1 -cpu=1 -cpuprofile=label.pprof
# Replace the final two benchmark components with ^n$/^FOR10$ for integers.
```

## Validation

Validation includes SIMD and portable exact-count tests, all short counts
through 80, accumulator-flush boundaries, 65,536-row inputs, byte alignments
0–31, dirty padding, impossible needles, single-lane matches, and zero
allocations. Packed tests also pass race detection with strict pointer
checking. The full SIMD query suite, root build and vet, and focused portable
query integration test pass. Linux ARM64 and AMD64 test binaries cross-compile; AMD64 retains
the scalar counter and has no speedup claim here.

Disassembly contains NEON table lookups, shifts, comparisons, subtractions,
and reductions with hoisted constants and no helper calls or vector spills
inside the vector body. Short inputs and remaining rows call the original
scalar counters. No new `unsafe` import is needed.

The old `BenchmarkCompactPrimaryStripeCountryScan` failed on the unmodified
baseline because its dictionary-only entry point does not support the codec
chosen by its current corpus. Its separate repair uses the current spelling
count API. It is not used in the comparison above.
