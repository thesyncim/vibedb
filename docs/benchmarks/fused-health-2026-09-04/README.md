This experiment isolates the health-status path in the fused runtime after merging main `fc7548a7`. Both arms contain the same catalog correctness fix: a concurrent certified read can install a just-committed catalog head before the publisher updates its local holder. The publisher now accepts only an exact match of that already-applied head, without replaying a write or weakening the catalog CAS.

The performance change replaces routine health revision snapshots with an authenticated fixed-size status response. The Raft owner still checks pending result settlement and the durable publication fence. Replica movement, learner installation and backup retain their full snapshot observations. Focused protocol, owner, quorum and race tests passed; deterministic catalog tests fail on the original source and pass with the shared fix.

Before is `494cf2aaf9f97779ca855833875024834f64a0d5`; after is `2184dca377127f0a5a5de76d061ab410bc49470d`. The recorded patch between them contains only the 12 health-change files. The runtime layout is identical: three serving processes, RF3, one SQL endpoint, fresh storage per fixture, and a total limit of 12 CPUs / 24 GiB including the client, with swap disabled. VibeDB, the shared client and CockroachDB are Linux/ARM64 executables on the same Linux 7.0.12-linuxkit Docker VM. Both VibeDB builds and the client embed Go 1.27.0-X:simd and `GOEXPERIMENT=simd`; the runner refuses missing SIMD or OS/architecture settings. CockroachDB uses the same pinned official 26.3.1 image as the preceding experiment.

The completed campaign ran from 15:35:34 to 15:39:19 UTC on 2026-09-04. Each fixture uses 1,024 rows of 256-byte payloads, C1/C8, five workloads, two repetitions and untimed warmup/setup/verification. All 120 trials / 153,600 raw latency samples pass validation with zero SQL errors. See the [independent audit](audit-summary.md) for per-cell throughput, p99, locality and qualifications. Throughput geomeans improve 6.8% and 13.6% over the before arm in the two orders. After/CockroachDB geomeans remain 0.607x and 0.450x. Write gains occur in both orders, but vary substantially. Two first-order p99 cells regress beyond the 10% guardrail. Health publication remains active; health-controller warning lines are retained and are not all shutdown-only.

This does not establish the 2x CockroachDB objective, multi-machine scalability, or failure/recovery parity. The full fused physical-node qualification gate remains unresolved. These short measurements are not the registered full benchmark matrix.

After all measurements and verification, the bounded cleanup forcibly stopped one CockroachDB process in each order (exit 137). All VibeDB supervisors exited cleanly. These are post-measurement cleanup results and provide no crash/recovery qualification.

The earlier attempt using `b6e41fe7` and `6aca5f18` stopped at an untimed candidate CREATE error after the baseline completed. That failure exposed the catalog race above. Its baseline samples are retained separately and never included in the comparison. The rerun applies the correctness fix equally to both arms.
